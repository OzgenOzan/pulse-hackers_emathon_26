# Şahin Göz v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Task progress is tracked in OMP, not in this document.

**Goal:** Deliver an offline, reproducible emergency-department simulation in which clinicians can act on all three alert levels and see exactly why they fired.

**Architecture:** A pure evaluator emits scored evidence and candidates. A deterministic scenario player emits chronological batches; a single locked session owns alert transitions, actions, and audit records. A same-origin React client polls a local FastAPI application.

**Tech Stack:** Python 3.11+, FastAPI, Pydantic v2, Uvicorn, PyYAML, pytest, httpx; Node 20+, npm, React, TypeScript, Vite and CSS.

**Spec:** [`00_omp-initial-draft.md`](../../../00_omp-initial-draft.md); the three source PDFs are read-only. The execution request preapproves the design and branch `feat/sahin-goz-v0` in this checkout and names SDD for the independent tracks. The controller owns the sequential contract and integration phases.

## Global Constraints

- No real patient data, authentication, DB, cloud, real HBYS/monitor/HL7/FHIR integration, or external calls at runtime. Bind to loopback. Browser calls only the local API.
- Preserve the literal §4 YAML. No extra clinical thresholds. Mark clinical ambiguities in STATUS and label the entire app simulated / decision support only.
- Prioritize and push verified P0 before P1. P2 is backlog only. Commit owned changes via the selective commit tool. No main commits, force pushes, or PR merges.
- Each behavioral task starts with its named observable assertion and demonstrates RED → GREEN. See the numbered sections below for files, checks, and dependencies.

## Review Focus

- A blocked RED remains latched when its score falls; only an explicit accepted acknowledgement releases it (Tasks 3, 7, 11).
- A result received after one boundary must not score retroactively when several boundaries are crossed in one request (Tasks 5, 7).
- Repeated tests must match distinct orders; an outstanding repeat blocks GREEN; an older critical result must not survive a new normal result of that test (Tasks 2, 7).
- A manual vital reading during a disconnect may clear overdue-vitals but not the independent monitor gap (Tasks 2, 7).
- Retrying a completed acknowledgement cannot create a second simulated discharge/transfer or an audit duplicate (Task 7).

### Task 5: Deterministic clock and event application

**Review:** per-task — persisted scenario format

**Files:** `backend/app/sim/{clock,player}.py`, `backend/app/adapters/{source,simulator}.py`, `backend/tests/test_player.py`.

**Produces:** `Scenario.load(path)`, `Player(scenario, cycle_minutes)`, `reset()/advance_to(target)` yield ordered `Frame(time, events, evaluate)` entries; `apply_event(patients, event, time, disconnected)` changes only scenario domain data. `SimClock` exposes play/pause/step/reset and accepts a monotonic wall clock. `DataSource` protocol exposes available scenarios and loads an ID, not an arbitrary path.

1. Write tests for stable same-time insertion order, pre-start data, an event at the boundary applied first, between-boundary event application without retroactive influence, paused time, end cap, and reconnect at the next boundary. Implement and verify `tests/test_player.py`.
2. Pair a lab result with the oldest pending order of that test. Snapshot profiles awaiting an `arrival` event do not exist in the in-zone list until applied. Pause freezes the current simulated time; speed changes anchor at the current one. All crossed cycles are delivered in order with no background work.
